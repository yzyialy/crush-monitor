# Crush 好感监控器（本机版）

一个用 Jev 分析你和 Crush、或对象聊天的小工具。帮你读懂一点对方的情绪和想法，也看看自己的回复哪里没表达好、可以怎么调整。

**本版本机运行**：没有账号、没有登录、没有服务器端数据库。装在自己电脑上，用**你自己的 API Key**，聊天记录存在浏览器本地、不上传任何第三方平台（分析时会把相关片段发给模型服务商，见下）。

> ⚠️ **这份代码是 AI 写的**：除了上游原作者那一版，本仓库全部改动由 AI 完成，维护者不懂编程。**遇到问题请直接让 AI 去修**（怎么写、看哪份文档，见 [DISCLAIMER.md](DISCLAIMER.md)）。
>

## 特点

- **微信风格界面**：还原聊天气泡，分析结果直接显示在消息下方。
- **情绪与意图**：每句两行标签，从 12 类情绪、35 类意图中分别展示概率最高的三项。
- **好感度与回复评级**：顶部显示好感信号评分，自己的回复按 SSS 到 D 分档，并给出下一步建议。
- **深度解读（可选，默认关闭）**：接入第二层模型，把这段交流里值得注意的信号整理成「发生了什么 / 和她平时相比 / 你可能漏掉的信号 / 可能是什么意思 / 为什么这么判断 / 目前不能确定 / 接下来观察什么」。填了 DeepSeek Key 再打开。
- **长期观察**：按人记录她自己的行为基线（回复快慢、长短、主动程度等），下次不再从零开始，而是能看出「这一次和她平时哪里不同」。**数字全部由程序计算，模型只负责解释。**
- **历史对话**：每段聊天单独记录、按最近更新排序，随时可以点回去看当时的内容**和已经分析好的标签**（不会重新花钱调模型）；「开始新对话」只新开一段，**不删除任何历史**；每段都能改名。
- **语音 / 图片 / 表情包可补描述**：微信复制出来只有占位符，在占位符后面补一句描述，AI 才知道那是转述而不是原文（见下）。
- **粘贴后不自动分析**：输入框足够大，可以先把描述补好、错字改掉，确认无误再点「分析聊天」。
- **不静默失败**：任何「点了没反应」都会在页面顶部用红条写明原因，并写进本机日志（只记错误文本，不记聊天内容）。

## 长期观察有什么、没有什么

**有**：她平时回复大概多快多长、会不会主动开口、有哪些口头禅、几次对话里反复出现的模式、你亲自确认过的事实、以及你在这个账号下的反馈记录。

**没有**：人格诊断、依恋类型标签、「她喜欢你」的概率、情绪操纵建议、自动发消息或自动回复。

**长期模式只由程序统计产生**（至少 3 段对话支持，涉及一起活动这类解释需要 4 段）；模型自己的推测**永远不会**自动写成长期结论，只有你确认过的才会被记成事实。被你的纠正推翻的推断不会删除，以后可以复盘。

历史样本不足时（少于 3 次对话）系统会直接说明，不会假装已经认识这个人。

## 为什么用 Jev

Jev 是 TypeSafe 推出的结构化判断模型，直接返回分类、评分和概率。这款工具主要需要逐句判断，不需要生成长篇回答，正好适合它的输出方式；情绪和意图也可以放在同一次请求里并行分析。

- [创始人 Diogo Almeida 的 Jev 首发推文（2026-09-15）](https://x.com/CompleteSkeptic/status/2099925682726002904)
- [官方模型介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- [申请 API Key：TypeSafe 控制台](https://console.typesafe.ai/)

## 快速开始

### 需要什么

| 项 | 要求 |
|---|---|
| Node.js | **22.12 或更高**（建议 24 LTS） |
| TypeSafe API Key | 必需，第一层分析用。[申请地址](https://console.typesafe.ai/) |
| DeepSeek API Key | 可选，只有想用「深度解读」才需要 |

不需要服务器、不需要域名、不需要数据库。

### 装起来（3 分钟）

```sh
# 1. 装依赖
npm ci --include=dev

# 2. 生成 .env（已存在则不会覆盖），然后填入自己的 Key
npm run setup
#   TYPESAFE_API_KEY=your_api_key
#   HOST=127.0.0.1        # 建议就用默认值，只允许本机访问
#   PORT=3178

# 3. 构建前端并启动
npm run build
npm start
```

打开 **http://127.0.0.1:3178/** 就能用了。使用时保持终端运行；下次只要 `npm start`。改了 Key 重启即可。

不想构建也行，开发模式更省事：

```sh
npm run dev            # 打开 http://127.0.0.1:5178/
```

> **请用 `127.0.0.1` 或 `localhost` 打开。** 这个版本没有登录，如果改成让局域网/公网访问（`HOST=0.0.0.0`），任何能连上这个端口的人都能看到你的聊天记录，而且明文 HTTP 下密码类信息会被抓包——虽然本版没有登录，仍**强烈建议只监听本机**。要用别的设备看，用 SSH 端口转发：`ssh -L 3178:127.0.0.1:3178 你的电脑`，然后本机访问 `http://127.0.0.1:3178/`。

## 怎么用

1. 在电脑版微信里多选聊天记录，复制并粘贴到网页输入框。
2. 选择哪个昵称是你，点「分析聊天」（第一次会问你哪个昵称是你，选完点「开始分析」）。
3. 查看情绪、意图和回复评级，点击标签展开详情。
4. 有新聊天时继续粘贴，结果会随上下文更新；想换一段就点「开始新对话（保留历史）」，旧的在顶部「历史对话」里随时能翻回去。

支持微信的「昵称 → 时间 → 正文」格式，也支持 `我：…` / `对方：…`。**仅分析你粘贴的文字，不读取微信数据库、不后台监听。**

### 语音、图片、表情包怎么让 AI 知道

微信复制出来的语音、图片、表情包只有 `[语音]`、`[图片]`、`[动画表情]` 这样的占位，正文是看不见的。**在占位后面直接写一句描述就行**：

```
对方 21:00
[语音] 她说周末要加班，可能来不了

对方 21:02
[图片] 一张加班工位照片，屏幕上全是代码

对方 21:04
[动画表情] 一只猫笑得打滚
```

- 补了描述 → 会被当成「这条消息的内容」参与分析，气泡下方会标出「语音 / 图片 / 表情包 · 你补充的描述」，AI 收到的说明是「这是用户手动转述，不是原始文字」。
- 不补描述 → 跳过、不参与分析，气泡下方会标出「没有补充内容，这条不会参与分析」。
- 统计口径只认你写的那段描述，不带 `[语音]` 这类标记，所以「回复长度」之类的数字不会被占位符撑大。

### 历史对话 / 开始新对话

- 顶部「**历史对话 N**」列出这个人的全部聊天段：每段显示 `第 N 段 · 时间 · 第一句摘要`、条数、最近一条时间；当前那段标「当前」。
- 点任意一段 → 把当时的内容**和已经分析好的标签**调回界面（不重新调用模型，不花额度）。
- 「改名」给某段起个好记的名字（留空恢复自动命名）；「删除」只删那一段，要二次确认。
- 「开始新对话（保留历史）」= 新开一段空的记录，**不删除任何历史**，旧的在列表里随时能回去。

## 隐私与数据

- 聊天记录、分析标签、长期观察档案全部存在**你这台电脑的浏览器 localStorage** 里；换浏览器、无痕窗口、清理浏览数据都会丢，**也没有跨设备同步**（本机版没有服务端）。
- API Key 只在你本机 `.env` 文件里，**永不下发到浏览器**；仓库有测试盯着这条。
- 分析时会把相关聊天片段发给 TypeSafe（用深度解读时还会发给 DeepSeek），这是工具工作的前提。
- 详细的数据流向、第三方接收方、以及"这个工具不会做什么"见 **[PRIVACY.md](PRIVACY.md)**。

## 排障

| 现象 | 处理 |
|---|---|
| 页面打不开 | 确认终端还在跑、地址是 `http://127.0.0.1:3178/` |
| 点「分析聊天」或「开始分析」没反应 | **看页面顶部的红条**——现在所有失败都会写明原因；同时日志在 `logs/server.log` |
| 报 `crypto.randomUUID is not a function` | 说明你在用**明文 HTTP + 非 localhost** 的地址打开（比如局域网 IP）。这类浏览器 API 只在安全上下文存在。改用 `127.0.0.1` 或 SSH 端口转发 |
| 分析报「聊天结构或长度不符合要求」 | 单次别贴太长，或用「继续粘贴」分批 |
| 「深度解读」按钮不可用 | 需要在 `.env` 里填 `DEEPSEEK_API_KEY` 并设置 `DEEP_ANALYSIS_ENABLED=true`，然后重启 |
| 换电脑/清缓存后记录没了 | localStorage 是本机、单浏览器绑定；本机版没有同步机制 |

## 开发

React 19 + TypeScript + Vite + Express，使用 TypeSafe SDK 调用 `jev-1.13.0`，深度解读通过官方 Responses API 调用 DeepSeek。

```sh
npm run dev        # 开发模式：http://127.0.0.1:5178/
npm test           # 全部测试：离线、不调用任何真实模型、不花额度
npm run check:live # 真实模型调用检查（会消耗你自己的 TypeSafe 额度）
npm run build      # 类型检查 + 构建前端到 dist/
```

**改代码前请先读 [`docs/AI-HANDOFF.md`](docs/AI-HANDOFF.md)**——那是写给 AI 的交接书（文件职责表、硬规则、常见改动索引、踩过的坑）。设计权威是 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

三条最容易被踩坏的红线：

1. **LLM 不得计算或改写任何数字**——基线、趋势、delta、模式只能来自 `shared/patterns.ts` 与 `shared/profile.ts` 的纯函数；
2. **`model_inferred` 永不自动升级为 `user_confirmed`**——只有用户确认能提升来源等级；
3. **失败必须说出来**——任何"点了没反应"的路径都要么显示原因、要么写进日志，不许静默吞掉。
