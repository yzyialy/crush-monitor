使用说明

一个帮你读懂微信聊天的小工具。它会把对方每句话的情绪和意图标出来，帮你看看自己的回复哪里没表达好，并在你攒了足够多的聊天之后，告诉你「这一次和她平时相比有什么不同」。

分析结果只当参考。AI 看不到你们现实里怎么相处，也不知道聊天之外发生了什么，怎么理解对方、怎么表达自己，最后还是靠你自己。

这份说明对应的是本机单机版：跑在你自己这台电脑上，没有账号、没有服务器数据库，数据留在这个浏览器里。

一、开始之前

你需要两样东西：

  1. 这台电脑上已经跑起来的本机版：终端里执行 npm start，看到 Crush Monitor（本机版）: http://127.0.0.1:3178 这一行就算成功。没有账号、不用登录。
  2. 一个浏览器：电脑上的 Chrome / Edge / Safari 都行。

如果终端里还多了一行 ⚠️ 没有找到前端构建产物 dist/index.html，说明你少跑了 npm run build：先跑它，再刷新页面。

二、打开就能用

在浏览器地址栏输入：

http://127.0.0.1:3178/

直接就是聊天界面，没有登录这一步。

数据存在这个浏览器的本地存储里：换浏览器、换用户、开无痕窗口都看不到同一份数据；清掉「网站数据」就等于删掉记录。

请一直用 127.0.0.1 这个地址打开。 不建议改用本机的局域网 IP（例如 http://192.168.x.x:3178/）： 那种地址在浏览器眼里不是「安全上下文」，历史上正是它导致页面上的加密接口不存在、点了分析没反应（这一版已经修好并加了回归测试，但仍然不推荐）；而且它意味着同一个网络里的任何人都能打开这个页面、看到你全部聊天记录——本机版没有登录这道门。

三、第一次分析：把聊天粘进去

  1. 在电脑版微信里，选中你想分析的聊天，右键 → 复制（可以一次多选几十条）。
  2. 回到网页，粘贴到下方那个大输入框里。
  3. 先别急着点分析——这一步很关键，见下一节。
  4. 确认内容没问题后，点右下角「分析聊天」（也可以按 Ctrl + Enter）。
  5. 如果这是第一次粘贴，会弹窗问你「哪个昵称是你」，选一下，确认。

粘贴之后不会自动开始分析，这是故意的：留出时间让你改内容。

确认弹窗里那个「开始分析」按钮在条件不满足时是点不动的（灰色），按钮下面会用红字写清楚为什么：「没识别到聊天记录」/「识别到 3 个说话人」/「请先点一下哪个昵称是你」。条件满足时那里会显示一句灰色说明：确认后会先把这段记录存进这台电脑的浏览器里，然后开始逐句分析。

四、语音、图片、表情包：补一句描述

微信复制出来的语音、图片、表情包只有个占位符，正文是看不见的。在占位符后面直接写一句描述就行：

对方 21:00
[语音] 她说周末要加班，可能来不了

对方 21:02
[图片] 一张加班的工位照片，屏幕上全是代码

对方 21:04
[动画表情] 一只猫笑得打滚
  • 补了描述的：会当成这条消息的内容参与分析，气泡下方会标出「语音 / 图片 / 表情包 · 你补充的描述」。
  • 没补描述的：和以前一样跳过、不参与分析，气泡下方会标出「没有补充内容，这条不会参与分析」。

你补的描述会被明确标注成「这是用户手动转述，不是原始文字」再交给 AI，所以 AI 不会把它当成对方打出来的字。

五、结果怎么看

分析完成后，聊天区会变成这样：

位置内容
每句话下面对方消息显示「情绪」和「意图」标签（各三项概率）；你自己的消息显示「回复评级」
点标签弹出这一句的详细解读
底部「我的发挥」你在这段对话里的整体表现评级
底部「下一步」这段对话结束处适合做的方向
「深度解读」按钮让 AI 把这段交流整理成一段完整解读（需要几秒，会消耗你自己的 API 额度）
「长期观察」按钮你和她之间的长期档案，详见第八节

「深度解读」里看什么（它有七个区域）：

  1. 发生了什么 —— 客观事实
  2. 和她平时相比 —— 这次和她自己过去多次对话的水平差在哪（这是最有价值的一块）
  3. 你可能漏掉的信号 —— 你也许没注意到的社交信号
  4. 可能是什么意思 —— 并列的几种解释，不是唯一答案
  5. 为什么这么判断 —— 点进去能看到支持判断的原话
  6. 目前不能确定 —— 系统自己承认不知道的部分
  7. 接下来观察什么 —— 不是「你该怎么回」，而是下次留意什么

六、历史对话：翻回以前那一段

聊过几次之后，记录会分成好几「段」。顶部那个「历史对话 N」（N 是段数）就是总入口：

  • 每一行显示：名字 + 条数 + 最近一条时间 + 第一句摘要，当前正在看的那段标着「当前」。
  • 名字默认长这样：第 2 段 · 09-21 17:19 · 在干嘛。带上序号和时间是故意的——同一段聊天重复粘贴时，光看第一句会以为「每段名字都一样」。
  • 点一行 = 打开那一段：当时的聊天和已经分析好的情绪/意图标签一起回到界面，不会重新调用模型、不消耗额度。
  • 改名：点「改名」输入新名字；留空 = 恢复自动命名。
  • 删除：点「删除」会二次确认，只删那一段，长期观察（基线、记忆、模式）不受影响。
  • 列表按最近更新排序，最近聊过的在最上面。改名不会改变顺序（改完名那段不会跳到最前面）。

想开一段新的，又不想丢掉旧的

打开「聊天设置」（左上角齿轮，或右上角「⋯」），点 「开始新对话（保留历史）」：

  • 界面清空，本机会新开（或复用一段已经空着的）记录并切过去；
  • 下一次粘贴就写进这一段，旧记录一条都不会删，随时能在「历史对话」里翻回去；
  • 顶部的 +（新聊天）也是同一个行为：清空当前视图、开新的一段。

改「对方称呼」

同一个设置面板里的「对方称呼」可以随时改（例如从默认的 Crush 改成 小满）：

  • 改的是显示名——出现在顶部和「历史对话」列表里；
  • 不影响任何一条聊天记录，也不会把长期档案拆成两份（档案还是同一个人的）。

点了没反应？看顶部的红条

任何「点下去却没有结果」的情况，页面顶部都会弹出一条红色说明（旁边有「知道了」可以关掉），例如：

  • 「没能把这段聊天保存到本机：…」——浏览器不让写本机存储（无痕窗口、禁用了网站数据），或存储满了（一般 5MB 左右）；
  • 「这次没有新增消息：…」——这段内容之前导入过了，所以没有重新分析（想重跑点「继续分析」）；
  • 「操作没有完成：…」——页面里的异常原文。

终端里同时会有一行 [client-error] scope=... msg=...：只有错误文本、页面路径与浏览器信息，没有聊天内容、没有密钥。真出问题时可以把那一行贴出来。

七、它会说什么、不会说什么

会说：她平时回复大概多快多长、会不会主动开口、有哪些口头禅、一次次对话里反复出现的模式。

不会说：「她是什么类型的人」「她是回避型」「她喜欢你的概率是 X%」，也不会教你用什么话术去操纵对方。这是产品的硬约束，不是能力不足。

另外要理解它的一个原则：「互动投入下降」不等于「关系变差」，更不等于「她不喜欢你」。它只描述可观察的行为变化，比如这次回复比平时慢、比平时短。原因可能是加班、生病、心情不好——工具不知道，你也不该直接下结论。

八、长期观察：用几次才准

点「长期观察」打开，里面有几块：

  • 历史样本：已经记录了几段对话。不满 3 段时会明确告诉你「历史样本还不足」，它不会假装已经认识这个人。
  • 最近明显变化：这次和平时比，哪些指标差得多。
  • 已确认事实 / 观察到的事实：从聊天里记下来的客观信息（例如「对方说这周末考试」）。
  • 观察中的模式：由程序统计出来的行为模式，例如「历史上她的回复通常很短（5 段对话，平均约 1.6 字）」。需要至少 3 段对话支持才会形成，涉及一起活动这类解释需要 4 段。
  • 常见表达习惯：例如「哈哈」在你的聊天里跨很多种语境出现，就会被标成"语气填充"，避免每次都被解读成"她很开心"或"她在掩饰"。

建议：连续粘贴 3~5 段不同日期的聊天，长期观察才会真正有用。第一段对话时它只知道这一次。

长期观察跨对话累积，跟「第几段」无关：「开始新对话」只是换一段新的聊天记录，不会清空基线、记忆和模式。

九、确认与纠错（很重要）

在「长期观察」里，你可以对一次解读做两件事：

1. 这个判断后来被证实了吗？ 选「基本正确 / 部分正确 / 不正确 / 还不知道」。如果你选了正确，它会再问你确认的是哪一部分——只有你明确勾选的内容才会被记成"已确认的事实"，其他仍然只是推测。

2. 不是这样，我来说实际情况 比如系统把「回复变短」理解成互动降温，而你知道那天她在发烧，就写：「不是，她那天只是发烧」。 系统会：把你这句记成你确认的事实 → 把相关的模型推断标成"已被推翻" → 但不删除历史推断，以后复盘还能看到"当时模型把回复变短解释成互动下降，后来确认是生病"。

你越是纠正它，后面越准。它永远不会把自己的猜测自动变成事实——只有你亲自确认的才会。

十、换电脑、换浏览器会怎样

数据跟着浏览器走，不跟着你走。 长期档案和聊天记录都存在这台电脑的这个浏览器里：

  • 刷新页面、关掉再打开：记录还在，会自动恢复到上次看的那一段（含已分析好的标签），不消耗额度。
  • 换一台电脑、换一个浏览器、开无痕窗口：看不到原来的数据，等于从零开始。
  • 想让数据跟着你走：用浏览器开发者工具的 Application → Local Storage，把 crush-monitor. 开头的键手工导出来，在另一台机器上贴回去（详见 docs/DEPLOYMENT.md 第六节）。

十一、你的数据在哪、谁能看

  • 数据存在这台电脑的浏览器本地存储（localStorage）里，不在任何服务器上，也不在第三方公司手里。
  • 服务端不保存聊天内容和档案：它只在你点分析时收到「这次要分析的消息 + 检索出来的相关记忆」，用完即弃。
  • 诚实说明：任何能打开这台电脑、并使用这个浏览器的人都看得到这些数据（本机版没有登录这道门）。别在公用电脑上粘贴你不想被别人看到的聊天。
  • 分析时会把当前相关的聊天片段发送给两个 AI 服务（TypeSafe 的 Jev、DeepSeek）用于生成结果，这是它工作的前提——"数据存在本机"不等于"分析过程离线"。
  • 你可以随时：删除单条记忆、清空历史基线、删除某个人的整份档案、在「历史对话」里删掉单独一段聊天，或者在「长期观察」里一次性清空全部长期数据与本机聊天记录。

十二、常见问题

打不开网页，只看到一段中文提示页？ 说明前端还没构建。在项目根目录跑 npm run build，然后刷新。终端里同时会打印同一句提示。

打不开网页（连提示页都没有）？ 先确认终端里服务还在跑，网址是 http://127.0.0.1:3178/。如果换了端口，地址栏里的端口也要跟着改。

点「分析聊天」后报错？ 先看顶部的红条，它会写清原因。常见原因：这段聊天里没有可读的文字（全是没补描述的图片语音）、服务端 .env 里的第一层 API Key 还没填（或填错了）、API 额度用完了、或者浏览器不让写本机存储（无痕窗口 / 存储满）。重试一次通常能过。

按钮是灰的、点不动？ 看按钮下面的红字：它会告诉你差什么（没识别到聊天、说话人超过两个、还没选哪个昵称是你）。

刷新页面后聊天没了？ 正常情况下不会——本机存储里存着，刷新后会自动恢复上次看的那一段（含已分析好的标签）。如果真没了，检查是不是换了浏览器/开了无痕窗口，或者清过「网站数据」。

清空之后刷新，旧聊天又回来了？ 现在不会了。设置里那个按钮叫「开始新对话（保留历史）」：它新开一段并切过去，下一次粘贴写进新段，旧记录留在「历史对话」里。

「深度解读」很慢或失败？ 它要调用更贵的第二层模型，正常需要 5~15 秒。失败不影响第一层的情绪/意图标签，可以稍后重试。它必须由你点按钮触发，不会自动跑。

历史列表里几段名字看起来一样？ 默认名字是「第 N 段 · 时间 · 第一句」，序号和时间不会重复。如果确实想区分得更清楚，点「改名」自己起个名字（改名不会改变列表顺序）。

能不能帮忙分析别人的聊天？ 技术上可以，但请尊重对方隐私，也别把分析结果当成对一个人的定论。
